# Black settings и flows

## Что здесь настраивается

Black branch — это логика для разрешённого трафика.

Основные элементы:

- JS Connect action
- JS bot detection
- flows

## JS bot detection

Это дополнительный этап проверки уже на стороне браузера. Перед показом black-контента странице внедряется скрипт `js/detect.js`, который выполняет выбранные тесты и только после их успешного прохождения запрашивает настоящий контент.

При провале любого теста контент не запрашивается, посетитель остаётся на white page, а клик сохраняется в Blocked clicks с reason, равным имени проваленного теста (например, `browserscreen`), или `timeout`, если интерактивный тест не дождался действия посетителя.

Тесты делятся на два типа:

- **Неинтерактивные** выполняются мгновенно при загрузке страницы, участие посетителя не требуется.
- **Интерактивные** ждут реального действия посетителя до истечения **Timeout**. Все включённые интерактивные тесты должны пройти: контент запрашивается, только когда выполнен каждый из них.

| Тест | Тип | Что проверяет |
| --- | --- | --- |
| **Mouse click / Touch start** (`pointerdown`) | Интерактивный | Реальный клик мышью или касание экрана. Боты без эмуляции пользовательского ввода отсекаются по таймауту. |
| **Text typing** (`keydown`) | Интерактивный | Нажатие любой клавиши. Подходит для десктопного трафика; на мобильном трафике без ввода с клавиатуры даст ложные срабатывания. |
| **Device motion** (`devicemotion`) | Интерактивный, только Android | Реальные изменения показаний акселерометра. На не-Android устройствах проходит автоматически, поэтому не мешает десктопному и iOS-трафику. |
| **Device orientation** (`deviceorientation`) | Интерактивный, только Android | Реальные изменения показаний гироскопа. На не-Android устройствах проходит автоматически. |
| **Audio engine existence** (`audiocontext`) | Неинтерактивный | Наличие `AudioContext`. Отсутствие звукового стека характерно для урезанных headless-окружений и эмуляторов. |
| **Time zone** (`timezone`) | Неинтерактивный | Смещение часового пояса браузера должно попадать в диапазон **Minimum/Maximum allowed timezone**. Ловит ботов с серверным поясом, не совпадающим с ГЕО кампании. Поля диапазона показываются, только когда тест включён. |
| **Browser screen** (`browserscreen`) | Неинтерактивный | Наличие экрана и консистентность размеров. Провал означает: нулевой размер окна браузера (`outerWidth`/`outerHeight` — типичный признак headless без эмуляции окна), нулевой `screen.width`/`screen.height` или viewport шире физического экрана. |
| **WebDriver automation** (`webdriver`) | Неинтерактивный | Флаг `navigator.webdriver`, который браузер выставляет при управлении через CDP/WebDriver (Puppeteer, Playwright, Selenium без stealth). Также проверяется, что геттер этого флага не переписан JS-обёрткой — так ловятся боты, погасившие флаг stealth-плагином. |

## Flows

Flow — это отдельный маршрут трафика в black branch.

Flow включает:

- name
- filters
- steps
- distribution
- optimization settings

Порядок flows задаёт порядок проверки трафика. Чтобы изменить его, перетащите flow за ручку слева от названия. Когда ручка в фокусе, порядок также можно менять клавишами `↑` и `↓`.

При включённом [подсчёте уникальности](uniqueness.md) в filters доступно условие **Uniqueness** с областями Campaign и Flow. В Safe Page этого фильтра нет.

## Формат значений фильтров

В полях с операторами **in** и **not in** несколько значений перечисляются через запятую, без кавычек: `en,it`, `desktop,mobile,other`, `Android,iOS`. Пробелы вокруг запятых не учитываются, регистр букв не важен. Для этих операторов значение должно совпасть целиком; для частичного поиска используйте **contains** или **not contains**, если они доступны у выбранного фильтра.

Фильтры **Safe Page** и **Flow Filters** используют один общий набор правил. Дополнительные фильтры **Uniqueness**, **Conversion cap (campaign)** и **Conversion cap (flow)** доступны только в flows.

| Фильтр | Что проверяет | Операторы | Что писать |
| --- | --- | --- | --- |
| **OS** | Операционную систему из User-Agent/Client Hints. | **in**, **not in** | Названия, которые возвращает DeviceDetector: `Android`, `iOS`, `Windows`, `Mac`, `GNU/Linux`, `Ubuntu`. Несколько значений через запятую. |
| **OS version** | Версию операционной системы. | **in**, **not in**, **<=**, **>=** | Номер версии: `10`, `11`, `14`, `17.1`. Для сравнений используется сравнение версий. |
| **Device** | Тип устройства из DeviceDetector. | **in**, **not in** | `desktop`, `mobile`, `tablet`, `other` или точные типы из списка ниже. |
| **Bot** | Серверное распознавание бота по User-Agent. | **=** | Выберите **Yes** или **No** в интерфейсе. В сохранённых правилах используются `yes` и `no`. |
| **Brand** | Производителя устройства. | **contains**, **not contains**, **in**, **not in** | Например: `Apple`, `Samsung`, `Xiaomi`, `Huawei`. Для пустого/неизвестного бренда значение может быть пустым. |
| **Model** | Модель устройства. | **contains**, **not contains**, **in**, **not in** | Например: `iPhone`, `SM-G991B`, `Pixel 8`. У desktop-трафика модель часто пустая. |
| **Client** | Клиент/браузер из User-Agent. | **contains**, **not contains**, **in**, **not in** | Например: `Chrome`, `Mobile Safari`, `Firefox`, `Facebook`, `Instagram`. Для частичных семейств удобнее **contains**. |
| **ClientVer** | Версию клиента/браузера. | **<=**, **>=**, **in**, **not in** | Например: `120`, `120.0`, `17.4`. Для сравнений используется сравнение версий. |
| **Country** | Страну посетителя по IP. | **in**, **not in** | Двухбуквенные [ISO 3166-1 alpha-2 коды стран](https://ru.wikipedia.org/wiki/ISO_3166-1_alpha-2): `US`, `IT`, `RU`, `DE`, `BR`. |
| **Language** | Основной язык браузера из `Accept-Language`. | **in**, **not in** | Двухбуквенные [ISO 639-1 коды языков](https://ru.wikipedia.org/wiki/ISO_639-1): `en`, `it`, `ru`, `de`. |
| **UserAgent** | Полную строку User-Agent. | **contains**, **not contains** | Фрагменты строки: `facebook`, `facebot`, `curl`, `gce-spider`, `yandex.com`, `odklbot`. |
| **ISP** | ISP/ASN-организацию по IP. | **contains**, **not contains** | Фрагменты названия провайдера или датацентра: `facebook`, `google`, `amazon`, `azure`, `digitalocean`, `microsoft`. |
| **Referer** | HTTP-заголовок `Referer`. | **=**, **!=**, **contains**, **not contains** | Полный URL или фрагмент источника. Пустое значение разрешено, если нужно проверить отсутствие referer. |
| **Domain** | Домен кампании, на который пришёл трафик. | **in**, **not in** | Хост из текущего запроса, например `example.com`, `promo.example.com`. |
| **Host** | Хост из входящего запроса или переданный prefill `tds_host`. | **in**, **not in** | Обычно совпадает с **Domain** при прямом заходе. Полезен для серверных интеграций, где host может быть передан явно. |
| **VPN&Tor** | Результат проверки IP через включённые proxy/VPN-плагины. | **=** | Выберите **Detected** или **NOT Detected** в интерфейсе. |
| **IP Base** | Наличие IP в текстовой базе внутри папки `bases/`. | **in**, **not in** | Имя одного или нескольких файлов баз через запятую: `bots1.txt,bots2.txt`. В файлах можно использовать IP и CIDR-диапазоны. |
| **URL Parameter** | Наличие или значение query-параметра URL. | **in**, **not in**, **exists**, **not exists** | Первое поле — имя параметра, например `utm_source`; второе поле для **in/not in** — значения через запятую, например `fb,tt`. |
| **Uniqueness** | Уникальность посетителя в кампании или flow. | **is unique**, **is not unique** | Доступно только в flows после включения [подсчёта уникальности](uniqueness.md). Область: **Campaign** или **Flow**. |
| **Conversion cap (campaign)** | Суточный лимит конверсий по всей кампании. | `<`, `<=`, `=`, `!=`, `>=`, `>` | Доступно только в flows. Выберите статусы кампании и числовой дневной лимит. |
| **Conversion cap (flow)** | Суточный лимит конверсий текущего flow. | `<`, `<=`, `=`, `!=`, `>=`, `>` | Доступно только в flows. Считает только строки, привязанные к текущему flow. |

**Language** проверяет основной язык браузера из HTTP-заголовка `Accept-Language`. YellowTDS берёт самый приоритетный язык, приводит его к нижнему регистру и оставляет первые две буквы. Поэтому используйте двухбуквенные [ISO 639-1 коды языков](https://ru.wikipedia.org/wiki/ISO_639-1): `en`, `it`, `ru`, `de`, `fr`, `es`, `pt`, `tr` и т. д. Региональная часть не хранится: `en-US` и `en-GB` будут проверяться как `en`.

**Country** проверяет страну по IP и использует двухбуквенные [ISO 3166-1 alpha-2 коды стран](https://ru.wikipedia.org/wiki/ISO_3166-1_alpha-2) в верхнем регистре: `US`, `IT`, `RU`, `DE`, `BR`.

**Device** проверяет тип устройства, который вернула встроенная библиотека DeviceDetector. Допустимые значения:

`desktop`, `smartphone`, `tablet`, `feature phone`, `console`, `tv`, `car browser`, `smart display`, `camera`, `portable media player`, `phablet`, `smart speaker`, `wearable`, `peripheral`.

Также поддерживается удобный алиас `mobile`: он означает телефонный трафик и раскрывается в `smartphone`, `feature phone`, `phablet`. `feature phone` — кнопочный или простой телефон с браузером; `phablet` — крупный смартфон между телефоном и планшетом. Планшеты в `mobile` не входят; для них указывайте `tablet` отдельно. Например, `mobile,tablet` пропустит телефоны и планшеты, а `mobile` — только телефоны.

Алиас `other` собирает остальные редкие типы устройств: `console`, `tv`, `car browser`, `smart display`, `camera`, `portable media player`, `smart speaker`, `wearable`, `peripheral`. В `other` не входят `desktop`, `smartphone`, `feature phone`, `phablet` и `tablet`.

Фильтр **Bot** использует серверное распознавание User-Agent из DeviceDetector и позволяет выбрать **Yes** или **No**. Он работает до браузерной проверки и не заменяет отдельный этап **JS bot detection**. Если правило Safe Page блокирует бота, в Blocked clicks сохраняются reason `bot` и полный исходный User-Agent.

В каждом flow также доступны два самостоятельных суточных правила:

- **Conversion cap (campaign)** считает все принятые строки истории выбранных статусов по всей кампании.
- **Conversion cap (flow)** считает только строки текущего flow.

Можно выбрать оператор `<`, `<=`, `=`, `!=`, `>=` или `>`, несколько статусов кампании и числовое значение. В счёт входят принятые платные повторы и upsell-записи. Границы дня определяются campaign timezone, а подсчёт всегда использует время строки конверсии и не зависит от режима атрибуции статистики. Если flow перестал соответствовать CAP-правилу, YellowTDS проверяет следующий flow, затем TrafficBack.

## Steps

В step можно задать:

- folders
- redirect URLs
- weights
- load type

Порядок steps меняется той же ручкой слева от номера шага. Redirect является завершающим действием, поэтому такой step закреплён последним и не перетаскивается.

## MVT лендинга

У каждой folder-записи есть собственная секция **MVT**. У каждого Test кнопка Copy рядом с названием копирует его placeholder, например `#TEST1#`; вставьте его в HTML лендинга, затем добавьте текстовые или HTML-значения. YellowTDS равномерно и независимо выбирает по одному Value для каждого активного TEST и выполняет доверенную строковую замену; одинаковый placeholder можно использовать в HTML несколько раз.

TEST нумеруются по порядку создания. Values получают коды A, B … Z, AA и далее. Сохранённые Values нельзя редактировать: их можно только архивировать и добавить новый Value в конец. Архивированный TEST или Value остаётся в конфигурации и сохраняет свой номер или код, поэтому нумерация никогда не откатывается.

![Настройка MVT у folder-записи](../assets/screenshots/campaign-settings-mvt.png)

Один `clickid + step` всегда использует одну и ту же комбинацию лендинга и MVT. Новый клик сначала ищет сохранённый выбор в текущей PHP-сессии. Если включён **Save user path**, запасной выбор также хранится в существующей cookie `saved_paths` пять дней. Direct Load при F5 или Back читает назначение достигнутого step и не выбирает комбинацию заново.

Новые назначения используют только активные TEST и Values. Уже назначенный архивированный Value продолжает рендериться для существующего click, session или Sticky path, пока MVT включён. При выключенном MVT placeholders не заменяются: YellowTDS не сканирует и не исправляет HTML автоматически.
